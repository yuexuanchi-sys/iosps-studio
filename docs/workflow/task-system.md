# 任务体系（Milestones · Slices · Task Cards）

## 1. 三层结构

```
里程碑 Milestone（M0–M8）  —— 一个可以对外展示的阶段性成果
  └── 切片 Slice = 任务 Task（T-MMNN）  —— 一次会话左右能完成的、可验证的增量
        └── 验收标准 Acceptance Criteria  —— 一条一条可以检查的事实
```

### 里程碑

| ID | 名称 | 完成的标志 |
|---|---|---|
| M0 | 决策与环境 | 平台 / 分发定稿；仓库 + CI 冒烟测试打通 |
| M1 | 产品定义 | PRD 定稿；交互流程 / 线框；视觉规范；礼物素材清单 |
| M2 | 工程骨架与 CI | 多模块工程能在 CI 上构建、测试、出截图、出安装包 |
| M3 | 礼物体验 | 生日主页、回忆、彩蛋、祝福能跑通 |
| M4 | 照片编辑 | P0 修图功能完整可用 |
| M5 | 一键回忆短片 | 选素材 → 选模板 → 导出视频完整可用 |
| M6 | 视频剪辑 | 基础剪辑功能可用 |
| M7 | 增强功能 | P1 功能（抠图、海报、美颜、拼图、提醒 / 生日模式、许可页） |
| M8 | 打包分发与交付 | 朋友的设备上装好、验收通过 |

**最小礼物路径**（时间紧时）：M0 → M1 → M2 → M3 → M4 → M5 → M8；M6 / M7 生日之后通过更新补上。

### 切片怎么切（规则）

1. **垂直**：尽量端到端（模型 → 引擎 → 界面 → 验证），做完就能看到效果；纯基础设施切片除外。
2. **小**：一次会话（约 2–4 小时的 AI 工作量）能完成；超过就拆。
3. **可验证**：每条验收标准都能用 L0–L4 中的某个层级证明（见 [verification.md](verification.md)）。
4. **纯逻辑先行**：同一个功能，先切 L1 部分（Windows 上就能测），再切 L2 / L3 部分，减少 CI 往返。
5. **滚动细化**：只有即将开工的任务才写完整的任务卡（保持至少 3 张 `ready` 的卡）；更远的任务在 BOARD 上只占一行（`backlog`），不建文件。

## 2. ID 规则

- 任务：`T-MMNN`，MM = 所属里程碑（00–08），NN = 序号。**ID 一旦分配永不改变**（即使后来挪到别的里程碑）。
- 任务卡文件名：`tasks/T-MMNN-英文短横线标题.md`。
- 功能 `F-NN`、决策 `D-NN`、ADR `ADR-NNNN` 同样不复用。

## 3. 状态机

```
backlog ──细化──▶ ready ──开工──▶ in-progress ──自测通过──▶ review ──用户确认──▶ done
                    ▲                 │   ▲                     │
                    │                 ▼   │                     │
                    └──────────── blocked ┘ ◀───────────────────┘ (被打回)
任何状态 ──▶ dropped（不做了，写清楚理由）
```

| 状态 | 含义 | 需要任务卡文件吗 |
|---|---|---|
| `backlog` | 已识别，还没细化 | 否（只在 BOARD 占一行） |
| `ready` | 卡片写完整，依赖都满足或即将满足，可以开工 | 是 |
| `in-progress` | 正在做（**全局最多 1 个**） | 是 |
| `blocked` | 卡住了（在卡片和 STATUS 写明卡在什么上） | 是 |
| `review` | AI 自测完成，等用户验收（UI 观感、真机体验、决策确认） | 是 |
| `done` | 完成（满足 DoD） | 是 |
| `dropped` | 放弃 | 是（如果建过）|

## 4. 任务卡

模板：[tasks/_TEMPLATE.md](../../tasks/_TEMPLATE.md)。文件开头的 front matter 字段由 `check_repo.py` 校验：

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✅ | 必须和文件名一致 |
| `title` | ✅ | 中文标题 |
| `milestone` | ✅ | M0–M8 |
| `status` | ✅ | 见状态机 |
| `priority` | ✅ | P0 / P1 / P2 |
| `modules` | ✅ | 涉及的模块，或 `docs` / `infra` |
| `features` | | 关联的 F-NN |
| `depends` | ✅ | 依赖的任务 ID，没有就写 `none` |
| `verify` | ✅ | 需要的验证层级，如 `L0,L1` |
| `owner` | | `AI` / `用户` / `AI+用户` |
| `updated` | ✅ | 最后更新日期 |

## 5. 完成标准（Definition of Done）

一个任务要标 `done`，必须**全部**满足：

1. 验收标准全部打勾，每条都有证据（命令输出、CI run 编号、截图路径、用户确认）。
2. `verify` 字段要求的层级全部通过。
3. 代码任务：新增逻辑有单测；没有违反模块依赖规则；没有引入未登记许可证的依赖或素材。
4. 文档已同步：任务卡日志、BOARD、STATUS、受影响的 features / modules / ADR。
5. 需要用户判断的（观感、体验、决策），用户已经确认过。
6. `python tools/check_repo.py` 通过。
