# 会话协议（Session Protocol）

> [CLAUDE.md](../../CLAUDE.md) 是本文件的摘要。目标：**任何一次新会话，只看仓库文件就能准确接上，不依赖聊天记录。**

## 0. 核心理念

- **仓库就是记忆**：聊天记录会丢，上下文会被压缩，只有写进文件的才算数。
- **三个"真相来源"**，各管一件事，不重复：
  | 文件 | 回答的问题 | 粒度 |
  |---|---|---|
  | [STATUS.md](../../STATUS.md) | 现在在哪、下一步是什么、卡在哪 | 全局快照，覆盖式更新 |
  | `tasks/T-xxxx-*.md` | 这个任务要做什么、做到哪了 | 单个任务，进度日志追加 |
  | [logs/HANDOFF.md](../../logs/HANDOFF.md) | 每次会话发生了什么 | 时间线，只在顶部追加 |
- [tasks/BOARD.md](../../tasks/BOARD.md) 是任务的**索引**，状态必须和任务卡一致（由 `check_repo.py` 检查）。

## 1. 会话开始检查单

```
[ ] 1. 读 STATUS.md（阶段 / 当前任务 / 下一步 / 待决策 / 阻塞）
[ ] 2. 读 logs/HANDOFF.md 最上面一条
[ ] 3. 打开当前任务卡，读：目标、范围、验收标准、进度日志最后几条
[ ] 4. 运行 python tools/check_repo.py，确认仓库状态一致（不一致就先修）
[ ] 5. 判断能不能开工：
       - 依赖任务都是 done 了吗？
       - 有没有卡在"待用户决策"？→ 有就先问用户
       - 用户这次的指令和任务卡冲突吗？→ 冲突就先改任务卡并告诉用户
[ ] 6. 把任务卡状态改为 in-progress（如果之前是 ready），同步 BOARD
```

**用户只说"继续"的时候**：按上面的步骤接着做 STATUS 里的当前任务；当前任务卡在用户那里，就把需要用户回答的问题重新列出来。

## 2. 工作中的规则

| 情况 | 怎么做 |
|---|---|
| 任务比预想的大 | 拆成多个任务（新 ID），原任务缩小范围；在 BOARD 登记 |
| 发现新任务 / 新 bug | 在 BOARD 对应里程碑下加一行 `backlog`，不要顺手做（除非很小且就在当前范围里） |
| 需要做技术选型 | 写 ADR（Proposed），影响大的要问用户 |
| 需要用户提供东西（素材、账号、决定） | 写进 STATUS「待用户决策」（新 D-NN）并当场问用户 |
| 事实不确定 | 查证；查不到就标「待核实」 |
| 用户临时插入别的事 | 当前任务卡记一条"暂停于…"，把插入的事作为新任务或直接处理，结束时两边都写清楚 |
| 会话可能要结束了（上下文很长） | 提前做一次"会话结束检查单"，宁可多写不要漏写 |

## 3. 会话结束检查单

```
[ ] 1. 任务卡：更新 status；进度日志追加一条（日期 / 做了什么 / 验证证据 / 没做完的）
[ ] 2. 验收标准逐条打勾（只有真正验证过的才打勾）
[ ] 3. BOARD.md：同步状态
[ ] 4. 受影响的文档：features.md / modules.md（模块状态）/ ADR / PRD
[ ] 5. STATUS.md：当前任务、下一步（≥ 3 条）、待决策、阻塞、最后更新日期
[ ] 6. logs/HANDOFF.md 顶部追加交接记录
[ ] 7. python tools/check_repo.py → 0 error
[ ] 8. Git：按 D-05 的授权执行（未授权时只提示用户"有未提交的改动"）
[ ] 9. 给用户一个简短总结：做了什么、验证情况、需要用户做什么
```

## 4. 任务完成的判定（简版，完整的 DoD 见 [task-system.md](task-system.md)）

只有同时满足以下条件才能标 `done`：验收标准全部打勾 + 要求的验证层级通过（有证据）+ 文档已同步。需要用户确认的（UI 观感、真机体验）先标 `review`，用户确认后再标 `done`。

## 5. 交接记录模板

写在 [logs/HANDOFF.md](../../logs/HANDOFF.md) 顶部：

```markdown
## YYYY-MM-DD · 会话标题（一句话）
- **任务**：T-xxxx（状态变化：ready → in-progress → review）
- **完成**：…（列出产出的文件 / 功能）
- **验证**：L1 本地 swift test 通过 12/12；CI run #34 绿；截图见 …
- **未完成 / 遗留**：…
- **注意（坑）**：…（下一次会话最需要知道的事）
- **下一步**：…
```
